# Цель работы

Получить навыки работы с репозиториями и менеджерами пакетов.

# Ход выполнения

## Работа с репозиториями и пакетным менеджером DNF

1. Переход в каталог `/etc/yum.repos.d` и просмотр содержимого.  
   Определено наличие нескольких файлов конфигурации репозиториев: **rocky-addons.repo**, **rocky-devel.repo**, **rocky-extras.repo** и **rocky.repo**.  
   В файле `rocky.repo` отображаются параметры основного репозитория **BaseOS** и дополнительного — **BaseOS debuginfo**.  

   ![Просмотр содержимого каталога и файла rocky.repo](Screenshot_1.png){ #fig:001 width=80% }

2. Вывод списка доступных репозиториев.  
   На экране отобразились активные репозитории:  
   - **Rocky Linux 10 - BaseOS**  
   - **Rocky Linux 10 - AppStream**  
   - **Rocky Linux 10 - Extras**  

3. Поиск пакетов, содержащих слово *user* в имени или описании.  
   Найдено несколько библиотек и утилит:  
   - **libuser** — библиотека для управления пользователями и группами,  
   - **usermode** — инструменты для управления пользователями,  
   - **xdg-user-dirs** — управление пользовательскими каталогами и др.  

   ![Результаты поиска по слову user](Screenshot_2.png){ #fig:002 width=80% }

4. Поиск и изучение пакета **nmap**.  
   Утилита предназначена для сетевого сканирования и аудита безопасности. Команда `dnf info nmap` вывела подробную информацию о версии, размере и назначении пакета.  

   ![Информация о пакете nmap](Screenshot_3.png){ #fig:003 width=80% }

5. Установка пакета **nmap**.  
   При установке выполнялась проверка ключей GPG и установка зависимостей. После завершения команда подтвердила успешную установку.  
   Отличие между `dnf install nmap` и `dnf install nmap\*` заключается в том, что первая команда устанавливает только основной пакет `nmap`, а вторая — его дополнительные пакеты и зависимости (например, **nmap-ncat**).  

   ![Установка пакета nmap](Screenshot_4.png){ #fig:004 width=80% }

6. Удаление пакета **nmap**.  
   Сначала был удалён основной пакет `nmap`, затем дополнительно удалён связанный пакет **nmap-ncat**, входящий в состав `nmap*`.  

   ![Удаление пакета nmap](Screenshot_5.png){ #fig:005 width=80% }

7. Работа с группами пакетов.  
   Получен список доступных групп, после чего изучена группа **RPM Development Tools**, содержащая утилиты для сборки пакетов (например, **rpmbuild**).

## Использование rpm

1. Скачивание rpm-пакета **lynx**.  
   Сначала был просмотрен список доступных пакетов командой `dnf list lynx`.  
   Далее выполнена загрузка пакета с помощью `dnf install lynx --downloadonly`.  

   ![Загрузка пакета lynx](Screenshot_10.png){ #fig:010 width=80% }

2. Определение расположения загруженного пакета.  
   Пакет был сохранён в директории `/var/cache/dnf/appstream.../packages/`.  

3. Установка пакета с помощью команды **rpm**.  
   Для установки был использован файл `lynx-2.9.0-6.el10.x86_64.rpm`.  

   ![Установка пакета lynx](Screenshot_11.png){ #fig:011 width=80% }

4. Определение расположения исполняемого файла.  
   С помощью команды `which lynx` было определено, что бинарный файл находится в каталоге `/usr/bin/lynx`.  

5. Получение информации о пакете.  
   - `rpm -qf $(which lynx)` — показал, что исполняемый файл принадлежит пакету lynx.  
   - `rpm -qi lynx` — вывел сведения о пакете: версия, размер, лицензия, производитель, описание.  

6. Просмотр состава пакета.  
   - `rpm -ql lynx` — отобразил все файлы пакета, включая бинарные и конфигурационные.  
   - `rpm -qd lynx` — показал список файлов документации.  
   Дополнительно был просмотрен **man-мануал** утилиты `lynx`.  

   ![Список файлов пакета lynx](Screenshot_12.png){ #fig:012 width=80% }
   ![Файлы документации пакета lynx](Screenshot_13.png){ #fig:013 width=80% }
   ![Просмотр man-страницы lynx](Screenshot_14.png){ #fig:014 width=80% }

7. Проверка работы программы.  
   Текстовый браузер **lynx** был запущен под пользователем в отдельном терминале. Браузер корректно отобразил содержимое стартовой страницы Rocky Linux.  

   ![Запуск lynx](Screenshot_15.png){ #fig:015 width=80% }

8. Просмотр конфигурационных файлов и установочных скриптов.  
   - `rpm -qc lynx` — показал расположение конфигурационных файлов (`/etc/lynx.cfg`, `/etc/lynx-site.cfg` и др.).  
   - `rpm -q --scripts lynx` — вывел список установочных скриптов, которые выполняются при установке и удалении пакета. Эти скрипты используются для настройки окружения и правильного удаления файлов.  

   ![Конфигурационные файлы lynx](Screenshot_16.png){ #fig:016 width=80% }

9. Удаление пакета.  
   Командой `rpm -e lynx` пакет был успешно удалён из системы.  

## Установка и изучение пакета dnsmasq

1. Установка пакета **dnsmasq**.  
   Сначала был просмотрен список доступных пакетов командой `dnf list dnsmasq`.  
   Далее выполнена установка с помощью `dnf install dnsmasq`.  
   Исполняемый файл был найден в каталоге `/usr/sbin/dnsmasq`.  

   ![Установка и определение расположения dnsmasq](Screenshot_17.png){ #fig:017 width=80% }

2. Определение принадлежности файла пакету и получение информации.  
   - Команда `rpm -qf $(which dnsmasq)` подтвердила, что файл `/usr/sbin/dnsmasq` принадлежит пакету **dnsmasq**.  
   - Команда `rpm -qi dnsmasq` вывела подробную информацию о пакете: версию, размер, лицензию, дату сборки и назначение.  

3. Просмотр состава пакета.  
   - Команда `rpm -ql dnsmasq` показала список всех установленных файлов, включая бинарные, документацию и служебные данные.  
   - Команда `rpm -qd dnsmasq` отобразила перечень файлов с документацией.  
   Дополнительно был просмотрен **man-мануал** `dnsmasq`, где указаны его основные возможности (DNS, DHCP, PXE, TFTP).  

   ![Список файлов пакета dnsmasq](Screenshot_18.png){ #fig:018 width=80% }
   ![Документация и man dnsmasq](Screenshot_19.png){ #fig:019 width=80% }

4. Просмотр конфигурационных файлов.  
   Команда `rpm -qc dnsmasq` показала местоположение файлов конфигурации:  
   - `/etc/dnsmasq.conf`  
   - `/etc/dbus-1/system.d/dnsmasq.conf`  

5. Изучение установочных скриптов.  
   Команда `rpm -q --scripts dnsmasq` вывела скрипты, выполняемые при установке:  
   - **preinstall scriptlet** — создаёт системного пользователя и группу `dnsmasq`, необходимые для работы службы.  
   - **postinstall scriptlet** — выполняет настройку окружения после установки.  
   Эти скрипты нужны для корректного создания сервисных учетных записей и правильной интеграции пакета в систему.

6. Удаление пакета.  
   Командой `rpm -e dnsmasq` пакет был успешно удалён из системы.  


# Контрольные вопросы

1. Чтобы найти пакет **rpm**, содержащий файл `useradd`, используется команда:  
   **rpm -qf /usr/sbin/useradd**  
   (если файл уже установлен в системе) или:  
   **dnf provides */useradd** — для поиска пакета в репозиториях.  

2. Чтобы показать имя группы **dnf**, которая содержит инструменты безопасности, и просмотреть её состав, используют команды:  
   - **dnf group list** — выводит список всех доступных групп.  
   - **dnf group info "Security Tools"** — показывает содержимое выбранной группы.  

3. Чтобы установить **rpm**, загруженный из Интернета и отсутствующий в репозиториях, применяют команду:  
   **rpm -ivh имя_пакета.rpm**  
   или с учётом зависимостей:  
   **dnf install ./имя_пакета.rpm**.  

4. Чтобы убедиться, что пакет **rpm**, загруженный извне, не содержит опасных скриптов, используют команду:  
   **rpm -qp --scripts имя_пакета.rpm**.  
   Она показывает скрипты, выполняемые при установке и удалении.  

5. Чтобы показать всю документацию в пакете **rpm**, применяют команду:  
   **rpm -qd имя_пакета**.  

6. Чтобы определить, какому пакету принадлежит определённый файл, используется команда:  
   **rpm -qf /путь/к/файлу**.
