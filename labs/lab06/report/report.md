## Управление процессами  

1. Получены права администратора с помощью команды **su**.  
   Это позволило выполнять системные операции с повышенными привилегиями.  

2. Запущено три ресурсоёмких процесса командой `dd if=/dev/zero of=/dev/null &`.  
   Каждый процесс выполнялся в фоне, записывая данные в «чёрную дыру» (**/dev/null**).  

3. Для просмотра списка активных процессов была выполнена команда **ps aux | grep dd**.  
   В выводе отобразились процессы, содержащие в команде подстроку *dd*.  
   Запущенные процессы оказались в конце списка.  

   ![Отображение процессов dd](Screenshot_4.png){ #fig:004 width=80% }  

4. Один из процессов был выбран для изменения приоритета с помощью команды **renice**.  
   Приоритет был понижен на 5 единиц, что изменило его положение в планировщике задач.  

5. Для анализа иерархии процессов использована команда **ps fax | grep -B5 dd**.  
   Опция `-B5` показала процессы вместе с пятью строками выше совпадения.  
   Благодаря этому отобразилась цепочка: оболочка → su → bash → процессы dd.  

   ![Отображение иерархии процессов](Screenshot_5.png){ #fig:005 width=80% }  

6. По найденному PID корневой оболочки выполнена команда **kill -9 <PID>**.  
   В результате оболочка завершила работу, а вместе с ней были остановлены и все дочерние процессы dd.  
   Такой подход позволяет завершить сразу целую группу связанных процессов.  

## Задание 1. Работа с приоритетами процессов  

1. Запущено три фоновых процесса с помощью команды `dd if=/dev/zero of=/dev/null &`.  
   Каждый из них выполнялся независимо, загружая процессор.  

2. С помощью команды **renice -n 5 5235** для одного из процессов был изменён приоритет.  
   Его значение изменилось с **0** на **5** (понижение приоритета, процесс будет получать меньше ресурсов CPU).  

3. Повторная команда **renice -n 15 5235** изменила приоритет того же процесса с **5** на **15**.  
   Теперь процесс ещё ниже в очереди планировщика, что означает ещё меньшее выделение процессорного времени.  
   Разница между значениями **-5** и **-15** в том, что чем меньше число nice (включая отрицательные значения), тем выше приоритет.  
   В данном случае использование положительных значений увеличило «доброту» процесса, уступая ресурсы другим задачам.  

4. Для завершения всех запущенных процессов **dd** применена команда **killall dd**.  
   Все три процесса были успешно остановлены.  

   ![ЗРабота с приоритетами dd](Screenshot_6.png){ #fig:006 width=80% }

# Контрольные вопросы  

1. Обзор всех текущих заданий оболочки показывает команда **jobs**.  

2. Чтобы остановить текущее задание и продолжить его выполнение в фоновом режиме, используют сочетание клавиш **Ctrl+Z**, а затем команду **bg**.  

3. Для отмены текущего задания применяется комбинация клавиш **Ctrl+C**.  

4. Если доступ к оболочке недоступен, задание можно отменить, используя другую консоль и команду **kill** с указанием PID процесса или **killall** с именем команды.  

5. Для отображения отношений между родительскими и дочерними процессами используется команда **ps fax**.  

6. Изменить приоритет процесса с идентификатором 1234 на более высокий можно командой **renice -n -5 -p 1234**.  

7. Если запущено много процессов dd (например, 20), проще всего завершить их командой **killall dd**.  

8. Для остановки команды с именем *mycommand* используется команда **killall mycommand**.  

9. В утилите **top** для завершения процесса применяется клавиша **k**, после чего вводится PID нужного процесса.  

10. Чтобы запустить команду с достаточно высоким приоритетом, но при этом не перегрузить систему, используется команда **nice** с положительным значением (например, **nice -n 10 команда**). Это позволяет процессу работать, но отдавать ресурсы другим задачам при необходимости.
