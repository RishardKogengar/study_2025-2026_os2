## Изменение правил rsyslog.conf

1. Установлен пакет веб-сервера Apache. После завершения установки служба **httpd** была запущена и добавлена в автозагрузку.  

   ![Установка и запуск httpd](Screenshot_5.png){ #fig:005 width=80% }

2. Во второй вкладке выполнен просмотр журнала ошибок веб-службы в реальном времени. На экране отобразились сообщения SELinux и запуск Apache.  

   ![Просмотр error_log Apache](Screenshot_6.png){ #fig:006 width=80% }

3. В конфигурационный файл */etc/httpd/conf/httpd.conf* добавлена строка:  
   **ErrorLog syslog:local1**  
   Это позволяет перенаправлять сообщения об ошибках веб-службы в системный журнал.  

   ![Редактирование httpd.conf](Screenshot_7.png){ #fig:007 width=80% }

4. В каталоге */etc/rsyslog.d* создан новый файл **httpd.conf** с правилом:  
   **local1.* -/var/log/httpd-error.log**  
   Теперь сообщения httpd будут сохраняться в отдельный файл журнала.  

   ![Создание правила httpd.conf](Screenshot_8.png){ #fig:008 width=80% }

5. Перезапущены службы **rsyslog** и **httpd** для применения изменений.  
   В логах стали фиксироваться ошибки Apache в новом файле */var/log/httpd-error.log*.  

6. Создан дополнительный файл конфигурации **debug.conf** с правилом:  
   **\*.debug /var/log/messages-debug**  
   Это позволяет сохранять все отладочные сообщения в отдельный журнал.  

   ![Создание debug.conf](Screenshot_9.png){ #fig:009 width=80% }

7. После перезапуска rsyslog был запущен мониторинг отладочных сообщений в файле */var/log/messages-debug*.  
   С помощью команды `logger -p daemon.debug "Daemon Debug Message"` в журнал было отправлено тестовое сообщение. Оно отобразилось в окне мониторинга.

## Постоянный журнал journald

1. Получены полномочия администратора и создан каталог для хранения записей журнала:  
   **/var/log/journal**.  

2. Для каталога были установлены корректные права доступа, что позволило службе **systemd-journald** записывать в него данные:  
   - владелец изменён на **root:systemd-journal**  
   - заданы права доступа **2755**  

3. Для применения изменений был отправлен сигнал **USR1** службе systemd-journald. Это позволило перезапустить механизм записи без полной перезагрузки системы.  

4. Проверка работы постоянного журнала выполнена командой:  
   **journalctl -b**  
   На экране отобразились сообщения ядра и системных служб, начиная с момента последней загрузки системы.  

   ![Просмотр журнала после перезапуска](Screenshot_21.png){ #fig:021 width=80% }

# Контрольные вопросы

1. Для настройки работы демона **rsyslogd** используется конфигурационный файл **/etc/rsyslog.conf**, а также файлы из каталога **/etc/rsyslog.d/**.  

2. Сообщения, связанные с аутентификацией пользователей, хранятся в журнале **/var/log/secure** (в системах на базе RHEL/CentOS/Rocky) или в **/var/log/auth.log** (в Debian/Ubuntu).  

3. Если не изменять параметры ротации, то по умолчанию она выполняется **ежедневно** с использованием механизма **logrotate**.  

4. Для записи всех сообщений с приоритетом **info** в отдельный файл следует добавить строку:  `*.info /var/log/messages.info`

5. Для просмотра сообщений журнала в реальном времени используется команда:  
**tail -f /var/log/messages**  
или в случае systemd — **journalctl -f**.  

6. Чтобы просмотреть все сообщения для **PID 1** в интервале между 9:00 и 15:00, используют команду:  
**journalctl _PID=1 --since "09:00" --until "15:00"**  

7. Сообщения journald после последней перезагрузки системы можно увидеть с помощью команды:  
**journalctl -b**  

8. Чтобы сделать журнал journald постоянным, необходимо:  
- создать каталог **/var/log/journal**  
- назначить ему владельца **root:systemd-journal**  
- задать права доступа **2755**  
- затем выполнить **killall -USR1 systemd-journald** или перезагрузить систему.  

# Заключение

В ходе работы были изучены механизмы регистрации и анализа системных событий в Linux с использованием сервисов **rsyslog** и **systemd-journald**. Были рассмотрены методы настройки перенаправления сообщений веб-сервера Apache в системный журнал, организация отдельных лог-файлов для ошибок и отладочной информации, а также практическое применение инструментов мониторинга журналов в реальном времени. Дополнительно освоены приёмы фильтрации и выборки событий с помощью **journalctl**, а также настройка постоянного хранения журнала journald. Полученные навыки позволяют администратору эффективно контролировать состояние системы и своевременно реагировать на возникающие ошибки и сбои.
