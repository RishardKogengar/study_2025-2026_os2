# Цель работы

Получение навыков настройки базовых и специальных прав доступа для групп пользователей в операционной системе типа Linux.

# Ход выполнения  

## Управление базовыми разрешениями  

1. Вход выполнен под пользователем **root**.  
   Созданы каталоги `/data/main` и `/data/third`. Проверка показала, что их владельцем по умолчанию является **root**.  

   ![Создание каталогов /data/main и /data/third](Screenshot_1.png){ #fig:001 width=80% }  

2. Выполнено изменение владельцев групп каталогов: для **/data/main** установлена группа **main**, а для **/data/third** – группа **third**.  
   Проверка подтвердила правильное назначение групп.  

3. Для каталогов заданы права доступа `770`. Это значит, что владелец и группа могут читать, записывать и выполнять действия в этих каталогах, а все остальные пользователи полностью лишены доступа.  
   Повторная проверка показала корректное применение прав.  

4. Выполнено переключение на пользователя **bob**. Попытка перейти в каталог **/data/main** завершилась успешно. Пользователь **bob** смог создать в нём пустой файл *emptyfile*. Проверка показала, что файл создан и принадлежит bob.  
   Это объясняется тем, что у bob есть права записи в каталог через группу **main**.  

   ![Создание файла emptyfile в каталоге /data/main](Screenshot_2.png){ #fig:002 width=80% }  

5. При попытке пользователя **bob** перейти в каталог **/data/third** доступ был запрещён. Сообщение *Permission denied* подтвердило отсутствие у него прав.  
   Это произошло из-за того, что bob не состоит в группе **third**, а для остальных пользователей доступ к каталогу закрыт.  

## Управление специальными разрешениями  

1. Пользователь **alice** перешёл в каталог **/data/main** и создал два файла *alice1* и *alice2*.  

   ![Создание файлов alice1 и alice2 пользователем alice](Screenshot_3.png){ #fig:003 width=80% }  

2. Затем выполнено переключение на пользователя **bob**, который также входит в группу **main**.  
   При просмотре содержимого каталога были видны файлы alice. Попытка удалить их завершилась успешно — файлы *alice1* и *alice2* были удалены.  
   Это стало возможным потому, что в каталоге ещё не был установлен sticky-bit, а пользователи группы имели права на удаление файлов друг друга.  

3. Пользователь **bob** создал в каталоге файлы *bob1* и *bob2*.  

4. Далее под пользователем **root** для каталога **/data/main** были назначены специальные права: бит идентификатора группы (**setgid**) и **sticky-bit**.  

5. После этого пользователь **alice** снова создал файлы *alice3* и *alice4*. Проверка показала, что все новые файлы принадлежат группе **main**, что обеспечивается действием setgid.  

   ![Создание файлов alice3 и alice4 после установки setgid и sticky-bit](Screenshot_4.png){ #fig:004 width=80% }  

6. Попытка пользователя **alice** удалить файлы *bob1* и *bob2* завершилась ошибкой: система запретила выполнение операции.  
   Это связано с действием **sticky-bit**, который запрещает удалять чужие файлы в общем каталоге.  

## Управление доступом с использованием ACL  

1. Вход выполнен под пользователем **root**.  
   Для группы **third** были установлены права на чтение и выполнение в каталоге **/data/main**, а для группы **main** — аналогичные права в каталоге **/data/third**.  

   ![Назначение ACL для каталогов /data/main и /data/third](Screenshot_5.png){ #fig:005 width=80% }  

2. С помощью команды проверки ACL подтверждено, что в каталоге **/data/main** группа **third** имеет права на чтение и выполнение, а в каталоге **/data/third** такие права предоставлены группе **main**.  

3. В каталоге **/data/main** был создан новый файл *newfile1*. При просмотре его атрибутов ACL оказалось, что у файла нет наследованных прав для группы **third**. Это связано с тем, что для каталога ещё не были назначены права по умолчанию, и поэтому новые файлы не унаследовали дополнительные ACL-записи.  

   Аналогичная ситуация наблюдалась и при создании файла в каталоге **/data/third**: файл *newfile2* также не получил расширенные права для группы **main**.  

   ![Проверка ACL для файлов newfile1 и newfile2](Screenshot_6.png){ #fig:006 width=80% }  

4. Чтобы новые элементы автоматически наследовали дополнительные права, для каталога **/data/main** были заданы ACL по умолчанию для группы **third**, а для каталога **/data/third** — ACL по умолчанию для группы **main**.  

5. После этого в каталогах были созданы новые файлы. Проверка показала, что файлы автоматически унаследовали расширенные права:  
   - в **/data/main** группа **third** получила доступ на чтение и запись,  
   - в **/data/third** группа **main** также получила полный доступ к новым файлам.  

   ![Назначение ACL по умолчанию и проверка новых файлов](Screenshot_7.png){ #fig:007 width=80% }  

6. Для проверки ограничений доступа был выполнен вход под пользователем **carol**, который состоит в группе **third**.  
   При попытке удалить файлы *newfile1* и *newfile2* система вернула сообщение об отказе в доступе. Это связано с тем, что права ACL не позволяли удалять чужие файлы.  
   Попытка записи в файл *newfile1* также завершилась ошибкой, так как он был создан до назначения ACL по умолчанию и не унаследовал нужные права.  
   Однако запись в файл *newfile2* оказалась успешной, так как при его создании он получил расширенные права группы **third**.  

   ![Проверка доступа пользователя carol](Screenshot_8.png){ #fig:008 width=80% }  


# Контрольные вопросы  

1. Чтобы изменить владельца и группу файла, используется команда **chown**.  
   Пример:  
   chown alice:main myfile  
   Здесь владельцем файла *myfile* становится пользователь **alice**, а группой — **main**.  

2. Чтобы найти все файлы, принадлежащие конкретному пользователю, используется команда **find** с ключом `-user`.  
   Пример:  
   find /home -user alice  
   Данная команда выведет список всех файлов пользователя **alice** в каталоге */home*.  

3. Чтобы применить права на чтение, запись и выполнение для владельца и группы для всех файлов в каталоге */data*, не устанавливая никаких прав для остальных, используется команда:  
   chmod -R 770 /data  

4. Чтобы добавить разрешение на выполнение для файла, используется команда **chmod**.  
   Пример:  
   chmod +x script.sh  

5. Чтобы групповые права назначались всем новым файлам в каталоге, используется бит **setgid**:  
   chmod g+s /data/main  
   Теперь все новые файлы в каталоге будут наследовать группу каталога.  

6. Чтобы пользователи могли удалять только свои файлы, используется **sticky-bit**.  
   Пример:  
   chmod +t /data/main  
   Это позволит удалять только собственные файлы, даже если у других есть права записи в каталог.  

7. Чтобы добавить ACL, предоставляющий группе права на чтение всех файлов в текущем каталоге, используется команда:  
   setfacl -m g:main:r *  

8. Чтобы гарантировать, что группа получит права чтения для всех существующих и будущих файлов в каталоге и его подкаталогах, необходимо:  
   setfacl -R -m g:main:rX .  
   setfacl -R -d -m g:main:rX .  
   Здесь первая команда назначает права для существующих файлов, а вторая — задаёт права по умолчанию для новых файлов.  

9. Чтобы новые файлы создавались без прав для «других», необходимо установить **umask** в значение `007`.  
   Пример:  
   umask 007  
   В этом случае новые файлы будут доступны только владельцу и группе.  

10. Чтобы гарантировать защиту файла *myfile* от случайного удаления, можно установить атрибут **immutable**:  
    chattr +i myfile  
    После этого файл нельзя будет удалить или изменить до снятия атрибута.  

# Заключение  

В ходе работы были изучены и применены базовые и специальные механизмы управления правами доступа в Linux: стандартные разрешения, специальные биты (setgid и sticky-bit), а также расширенные списки контроля доступа (ACL). Практические шаги показали, как настраивать индивидуальные права для пользователей и групп, обеспечивая безопасный и удобный совместный доступ к файлам и каталогам.
