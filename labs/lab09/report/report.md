# Цель работы

Получить навыки работы с контекстом безопасности и политиками SELinux.

# Ход выполнения

## Управление режимами SELinux

1. Получены права администратора с помощью команды `su`.  
   Проверена текущая конфигурация SELinux. В отчёте команды `sestatus -v` отображаются основные параметры:  
   - **SELinux status:** включён;  
   - **SELinuxfs mount:** точка монтирования `/sys/fs/selinux`;  
   - **SELinux root directory:** основной каталог конфигурации `/etc/selinux`;  
   - **Loaded policy name:** активна политика *targeted*;  
   - **Current mode:** *enforcing* — режим принудительного контроля безопасности;  
   - **Policy MLS status:** поддержка многоуровневой безопасности включена;  
   - **Process contexts** и **File contexts:** показывают текущие метки безопасности процессов и файлов.  

   ![Просмотр статуса SELinux](Screenshot_1.png){ #fig:001 width=80% }

2. Команда `getenforce` подтвердила, что SELinux работает в режиме **Enforcing** (принудительном).  
   Далее режим был временно изменён на **Permissive** с помощью `setenforce 0`.  
   Повторная проверка (`getenforce`) показала, что система действительно перешла в разрешающий режим.  

   ![Изменение режима работы SELinux](Screenshot_2.png){ #fig:002 width=80% }

3. Для полного отключения SELinux открыт файл конфигурации `/etc/sysconfig/selinux` и изменено значение параметра `SELINUX=disabled`.  
   После сохранения файла система была перезагружена.  

   ![Отключение SELinux в конфигурационном файле](Screenshot_3.png){ #fig:003 width=80% }

4. После перезапуска проверена текущая конфигурация. Команда `getenforce` показала значение **Disabled**, что подтверждает полное отключение SELinux.  
   Попытка включить режим принудительного контроля (`setenforce 1`) завершилась сообщением о невозможности, так как SELinux был полностью выключен.  

   ![SELinux отключён](Screenshot_4.png){ #fig:004 width=80% }

5. Для повторного включения SELinux в файле `/etc/sysconfig/selinux` установлено `SELINUX=enforcing`.  
   После перезагрузки система запустила автоматическую процедуру восстановления меток безопасности (relabeling).  

6. После завершения перезапуска снова проверен статус SELinux.  
   Команда `sestatus -v` показала, что система работает в режиме **Enforcing**, а все контексты процессов и файлов восстановлены.  

   ![Система работает в режиме enforcing](Screenshot_5.png){ #fig:005 width=80% }

## Использование restorecon для восстановления контекста безопасности

1. После получения административных прав проверен контекст файла `/etc/hosts`.  
   Отмечено, что его тип безопасности — **net_conf_t**.  

2. Файл `/etc/hosts` скопирован в домашний каталог. После копирования контекст изменился на **admin_home_t**, так как операция копирования создаёт новый объект с контекстом текущего пользователя.  

3. Файл из домашнего каталога был возвращён обратно в `/etc`, после чего контекст остался неправильным — **admin_home_t**.  

4. Для восстановления корректного типа безопасности выполнена команда `restorecon -v /etc/hosts`.  
   В результате тип контекста был успешно изменён обратно на **net_conf_t**, что подтверждено повторной проверкой `ls -Z /etc/hosts`.  

5. Для массового восстановления контекстов безопасности на файловой системе создан файл `.autorelabel` в корневом каталоге и инициирована перезагрузка. Это действие запускает автоматическую перемаркировку всех объектов при старте системы.  

   ![Восстановление контекста безопасности и подготовка к перемаркировке](Screenshot_6.png){ #fig:006 width=80% }

## Настройка контекста безопасности для нестандартного расположения файлов веб-сервера

1. Получены права администратора и установлены необходимые пакеты `httpd` и `lynx`.  
   После успешной установки веб-сервера создан новый каталог `/web`, предназначенный для размещения пользовательского веб-контента.  
   Внутри каталога создан файл `index.html` с приветственным сообщением.  

   ![Создание каталога и файла для веб-сервера](Screenshot_7.png){ #fig:007 width=80% }

2. В конфигурационном файле `/etc/httpd/conf/httpd.conf` изменён путь к корневому каталогу сайта.  
   Стандартный путь `/var/www/html` был закомментирован, а вместо него указан новый каталог `/web`.  
   Также обновлён раздел `<Directory>` для разрешения доступа ко всему содержимому каталога `/web`.  

   ![Изменение DocumentRoot и настроек доступа](Screenshot_8.png){ #fig:008 width=80% }

3. После изменения конфигурации веб-сервер был запущен и добавлен в автозагрузку.  
   При первом обращении к `http://localhost` с помощью браузера `lynx` открылась стандартная тестовая страница Rocky Linux, что свидетельствует о корректной работе службы, но не об использовании нового каталога.  

   ![Тестовая страница веб-сервера по умолчанию](Screenshot_9.png){ #fig:009 width=80% }

4. Для предоставления веб-серверу доступа к новому каталогу `/web` назначен корректный контекст безопасности SELinux.  
   Выполнена команда `semanage fcontext -a -t httpd_sys_content_t "/web(/.*)?"`, после чего восстановлены метки безопасности через `restorecon -R -v /web`.  
   Изменения вступили в силу после перезапуска службы `httpd`.  

   ![Назначение контекста безопасности и перезапуск службы](Screenshot_10.png){ #fig:010 width=80% }

5. Повторное обращение к `http://localhost` подтвердило успешную настройку SELinux и работу веб-сервера с новым каталогом.  
   В браузере `lynx` отображается содержимое пользовательского файла `index.html` с надписью **“Welcome to my web server”**.  

   ![Отображение пользовательской страницы веб-сервера](Screenshot_11.png){ #fig:011 width=80% }

## Работа с переключателями SELinux

1. Получены административные права и просмотрен список доступных переключателей SELinux для службы FTP.  
   В списке найден параметр **ftpd_anon_write**, отвечающий за разрешение анонимной записи, изначально имеющий значение **off**.  

2. С помощью команды `semanage boolean -l | grep ftpd_anon` просмотрены все доступные параметры, их текущие состояния и описания.  
   Переключатель **ftpd_anon_write** позволяет включить или отключить возможность анонимной записи через FTP.  

3. Временное изменение состояния параметра выполнено с помощью команды `setsebool ftpd_anon_write on`.  
   Проверка `getsebool ftpd_anon_write` показала, что значение изменилось на **on**, но данное изменение сохраняется только до перезагрузки.  

4. Для постоянного применения изменений выполнена команда `setsebool -P ftpd_anon_write on`.  
   После повторной проверки через `semanage boolean -l | grep ftpd_anon` видно, что переключатель **ftpd_anon_write** имеет состояние:  
   - **on, on** — что означает включение как временной, так и постоянной настройки.  

   ![Работа с переключателями SELinux для FTP](Screenshot_12.png){ #fig:012 width=80% }

# Контрольные вопросы

1. Чтобы временно перевести SELinux в разрешающий режим, используется команда **setenforce 0**.  
   Она меняет состояние SELinux на *Permissive* до следующей перезагрузки системы.  

2. Для вывода полного списка всех доступных переключателей SELinux используется команда **getsebool -a**.  
   Она отображает имена и текущее состояние всех доступных boolean-переключателей.  

3. Для получения легко читаемых сообщений журнала SELinux необходимо установить пакет **setroubleshoot-server**.  
   Он обеспечивает анализ событий SELinux и их интерпретацию в удобном для администратора виде.  

4. Чтобы применить тип контекста **httpd_sys_content_t** к каталогу */web*, выполняются следующие команды:  
   **semanage fcontext -a -t httpd_sys_content_t "/web(/.*)?"** — добавляет новое правило контекста,  
   **restorecon -R -v /web** — применяет изменения ко всем файлам и подкаталогам.  

5. Для полного отключения SELinux необходимо отредактировать файл **/etc/sysconfig/selinux**,  
   изменив параметр **SELINUX=disabled** и затем перезагрузить систему.  

6. SELinux регистрирует все свои сообщения в системном журнале **/var/log/audit/audit.log**.  
   Этот файл содержит детальные записи о всех событиях безопасности, контролируемых SELinux.  

7. Чтобы узнать доступные типы контекстов, используемых службой FTP, можно выполнить команду  
   **semanage fcontext -l | grep ftp** — она отобразит все контексты, связанные с FTP-службами.  

8. Если сервис работает некорректно и необходимо проверить, связано ли это с SELinux,  
   самый простой способ — временно перевести систему в разрешающий режим с помощью **setenforce 0**  
   и проверить, устранена ли проблема. Если сервис заработал, значит, сбой действительно был вызван политикой SELinux.
